# Pre-Launch Production Audit — Yasmin Beauty Salon
**Date:** 2026-08-04 · **Auditor:** Claude Code · **Commit audited:** `2660ce3` (`main`, identical to deploy source)

---

## 0. Audit method and a material limitation — read this first

**I could not reach `https://yasminbeauty.salon`.** This session's egress proxy returned `403 CONNECT tunnel failed` for that host on every attempt, via both `curl` and the fetch tool. `res.cloudinary.com` is blocked the same way. This is an organization egress policy denial, not a site fault, and per the proxy's own guidance it must be reported rather than routed around.

Consequently this audit was performed against **the deployed source at commit `2660ce3`**, which I verified is byte-identical to `origin/main` and to the working tree. For a static Vercel deploy with no build step, the repo *is* the deploy artifact, so every finding below about HTML, CSS, JS, and locale content applies directly to production.

What I could **not** verify and have marked **MANUAL** throughout:

| Cannot verify | Why | Where the test script is |
|---|---|---|
| Response headers (HSTS, nosniff, CSP, Referrer-Policy, caching) | Needs a live request | §M-11 |
| HTTP→HTTPS redirect, apex vs `www` canonicalization | Needs a live request | §M-11 |
| Whether `/robots.txt`, `/sitemap.xml`, `/404.html` exist at the edge | Absent from repo, but Vercel can inject | §M-11 |
| Lighthouse scores, LCP/CLS/INP/TBT, page weight | Needs a real browser against the live origin | §M-8 |

| Backend enforcement of hours, duration, slot collisions | Backend out of scope + browser-observable only via live API | §M-1 |

**Three premises in the audit brief turned out to be wrong about the current deploy.** I've audited what is actually there:

1. **Google Analytics is not installed.** There is no `gtag`, no `googletagmanager`, no `dataLayer`, no measurement ID anywhere in any HTML or JS file. §10's questions are answered against that fact, and it changes the shape of the §2 capability-code finding (the leak is latent, not live — see P0-4).
2. **`data-i18n-html` is used zero times** and `language.js` has no handler for it. HTML-bearing translations are injected through a regex heuristic on `data-i18n` values instead. The XSS question in §3 has a clean answer — see §3 below.
3. **`<html lang>` is not static** — `language.js:39` sets `document.documentElement.lang = lang` on every switch. The brief's hypothesised P1 does not exist. The real (smaller) issue is the pre-JS value; see P2.

Anything blocked *because* the API is on HTTP is noted as blocked and skipped, per the out-of-scope rules. **P0-1 is not the mixed-content finding** — it is a different and worse problem, explained there.

## 1. Launch verdict

**No. This must not go in front of paying customers today, and the reason is a single line of code.** `js/config.js` sets `API_BASE_URL = 'http://chris-fedora:8080'` — a developer's LAN machine name that resolves to nothing on the public internet. Every network call the site makes goes there: loading available time slots, submitting the booking, viewing an appointment, cancelling, rescheduling. For a real customer on a real phone, the time-slot panel fails to "Couldn't load times," and the booking cannot be completed at all. **The revenue path is not degraded, it is entirely non-functional**, and the site currently offers no static fallback that surfaces the salon's phone number when the booking flow dies. Beyond that blocker: the phone field's validation pattern rejects the exact format its own placeholder tells customers to type; the About page ships a grey `placehold.co` box where the business photo should be; the appointment capability code is never stripped from the URL and `view-appointment.html` carries no `noindex`; the submit button stays clickable throughout the image upload, so a customer on a slow connection can create duplicate bookings; and the privacy policy does not disclose that hair photos are collected or that Cloudinary receives them. Fix P0-1 through P0-6 and re-test the booking flow end to end against the production API before launch. The P1 list — most of it Spanish-language gaps on a site serving Boyle Heights — should follow within the week.

## 4. P2 — Backlog

**i18n**
1. `form.services.perm` is `"Perm"` in both locales — Spanish should be `"Permanente"`. Same for `modal.home` / `nav.home` (`"Home"` → `"Inicio"`); `modal.home` is on both modals.
2. The Spanish `about.p` value has **no ñ or accents at all** (`duena`, `suenos`) plus six typos: `des`→`de`, `tambien`→`también`, `pais`→`país` (×2), `ganas a salir`→`ganas de salir`, `adelate`→`adelante`, `tabajo`→`trabajo`, `arreppentiras`→`arrepentirás`. The inline HTML fallback at `about.html:105-108` has the accents right but the same word-level typos, and closes with `</Strong>`. This is the owner's personal story, in her own language.
3. 30 orphaned locale keys referenced nowhere: `privacy.s01.num`–`s12.num`, `privacy.s12.name`, `privacy.meta`, `privacy.footer.copy`, `privacy.title`, `privacy.eyebrow`, `nav.home`, `common.btn.book`, `form.date.placeholder`, `services.blowdry.time`, `about.info2.*`, `about.info3.desc`, `view.status.*`.
4. Three `data-i18n` attributes point at keys that exist in neither locale: `privacy.s04.to-opt-out`, `privacy.s04.to-get-help`, `privacy.s07.right-to-delete` (`privacy-policy.html:191,194,250`). They are harmless — the parent's value already carries the `<strong>` markup and `switchLanguage` skips missing keys — but they are dead references.
5. `language.js:32` decides "is this HTML?" with the regex `/<\/?[a-z][\s\S]*>/i`. Fragile: any future translated string containing a `<` followed by a letter gets `innerHTML`-ed. **No security issue today** — see §3 below — but worth replacing with an explicit convention.
6. Flatpickr's month and weekday names are always English; no `l10n/es.js` is loaded and the instance locale never changes with the site language.
7. `formatTime()` (`book-appointment.js:383`, `view-appointment.js:425`) uses `toLocaleTimeString([], …)` — the *device* locale, not the site language. A Spanish user on an en-US device sees English AM/PM; a user on a 24-hour-clock device sees `14:00` where the rest of the site says `2:00 PM`.
8. `showBookingSummary()` hardcodes the English `" at "` (`book-appointment.js:341`, `view-appointment.js:299`).
9. `view-appointment.js:170-191` hardcodes three English strings: `"Loading times..."`, `"Couldn't load times. Please try again later."`, `"No times available this day."`.
10. `view-appointment.js:414-418` `serviceLabel()` title-cases the raw enum (`BABY_HIGHLIGHT` → `"Baby Highlight"`) — never translated, and inconsistent with the booking page, which correctly reads the translated `<option>` label.
11. `book-appointment.js:280` captures `timeSlotContainer.innerHTML` at module-eval time, before `switchLanguage` has resolved. After a successful booking the panel is restored to the **English** empty state.
12. `language.js` cannot translate any attribute except `placeholder`. Untranslated across all pages: `<title>`, `aria-label="Toggle menu"`, `aria-label="Primary Navigation"`, `aria-label="Remove image"`, every `alt`, and the map `title`.

**Accessibility**

### P1-3 · `js/language.js` (full replacement)

Fixes: `switchLanguage` now reachable from classic scripts (P1-3); attribute translation for `alt`/`aria-label`/`title` and `<title>` (P2-12); guarded `localStorage` (P2-36); no accumulating listeners (P2-37); no crash when the language button is absent (P2-38).

```js
let translations = {};
let currentLang = 'en';
const SUPPORTED = ['en', 'es'];
const cache = {};

const languageBtn = document.querySelector(".language-btn");
const languageMenu = document.querySelector(".language-menu");

// localStorage throws in Safari private mode; degrade to "no persistence" rather than dying.
let store = null;
try { store = window.localStorage; } catch { /* unavailable */ }
const readLang = () => { try { return store?.getItem('ybs_lang'); } catch { return null; } };
const writeLang = (v) => { try { store?.setItem('ybs_lang', v); } catch { /* ignore */ } };

export function t(key) {
    return translations[key] ?? key;
}

// Expose to classic (non-module) scripts. view-appointment.js needs switchLanguage
// to re-translate content it injects after load.
window.t = t;
window.switchLanguage = switchLanguage;

// Attributes a translation can target, via data-i18n-<attr>.
const ATTRS = ['alt', 'aria-label', 'title', 'placeholder'];

export async function switchLanguage(lang) {
    if (!SUPPORTED.includes(lang)) lang = 'en';

    if (!cache[lang]) {
        const res = await fetch(`/locales/${lang}.json`);
        cache[lang] = await res.json();
    }
    translations = cache[lang];
    currentLang = lang;

    document.querySelectorAll('[data-i18n]').forEach(el => {
        const val = translations[el.dataset.i18n];
        if (!val) return;

        if (el.hasAttribute('placeholder')) {
            el.placeholder = val;
        } else if (/<\/?[a-z][\s\S]*>/i.test(val)) {
            el.innerHTML = val;
        } else {
            el.textContent = val;
        }
    });

    // data-i18n-alt="key", data-i18n-aria-label="key", data-i18n-title="key", ...
    ATTRS.forEach(attr => {
        document.querySelectorAll(`[data-i18n-${attr}]`).forEach(el => {
            const val = translations[el.getAttribute(`data-i18n-${attr}`)];
            if (val) el.setAttribute(attr, val);
        });
    });

    const pageTitle = document.querySelector('title[data-i18n-title]');
    if (pageTitle) {
        const val = translations[pageTitle.getAttribute('data-i18n-title')];
        if (val) document.title = val;
    }

    document.documentElement.lang = lang;
    writeLang(lang);

    const selected = document.querySelector(`.language-menu li[data-lang="${lang}"]`);
    if (selected && languageBtn) {
        const flag = selected.querySelector('.fi').className;
        const text = selected.textContent.trim();
        languageBtn.innerHTML = `
            <span class="${flag}"></span>
            <span>${text}</span>
            <span class="arrow" aria-hidden="true">▼</span>
        `;
        languageBtn.setAttribute('aria-label', translations['a11y.language'] || 'Change language');
    }

    // Only update state here — the click listeners are bound once, below.
    document.querySelectorAll('.lang-opt').forEach(opt => {
        const active = opt.dataset.lang === lang;
        opt.classList.toggle('active', active);
        opt.setAttribute('aria-pressed', String(active));
    });

    document.dispatchEvent(new CustomEvent('languagechange', { detail: { lang } }));
}

// Bound once at load, not on every switch.
document.querySelectorAll('.lang-opt').forEach(opt => {
    opt.addEventListener('click', () => switchLanguage(opt.dataset.lang));
});

if (languageBtn && languageMenu) {
    languageBtn.addEventListener("click", () => {
        const open = languageMenu.classList.toggle("show");
        languageBtn.classList.toggle("color-hover", open);
        languageBtn.setAttribute("aria-expanded", String(open));
    });

    document.querySelectorAll(".language-menu li").forEach(option => {
        option.addEventListener("click", () => {
            languageMenu.classList.remove("show");
            languageBtn.classList.remove("color-hover");
            languageBtn.setAttribute("aria-expanded", "false");
            switchLanguage(option.dataset.lang);
        });
        option.addEventListener("keydown", (e) => {
            if (e.key === "Enter" || e.key === " ") { e.preventDefault(); option.click(); }
        });
    });

    document.addEventListener("click", (event) => {
        if (!event.target.closest(".language-dropdown")) {
            languageMenu.classList.remove("show");
            languageBtn.classList.remove("color-hover");
            languageBtn.setAttribute("aria-expanded", "false");
        }
    });

    document.addEventListener("keydown", (e) => {
        if (e.key === "Escape" && languageMenu.classList.contains("show")) {
            languageMenu.classList.remove("show");
            languageBtn.classList.remove("color-hover");
            languageBtn.setAttribute("aria-expanded", "false");
            languageBtn.focus();
        }
    });
}

(async () => {
    const saved = readLang();
    const browser = navigator.language?.split('-')[0];

    const lang = SUPPORTED.includes(saved)
        ? saved
        : SUPPORTED.includes(browser)
        ? browser
        : 'en';

    await switchLanguage(lang);
})();
```

### P1-25 · Salon-timezone date bounds — `js/book-appointment.js:253-262` and `js/view-appointment.js:152-161`

Add near the top of `book-appointment.js`:

```js
// "Today" must mean today in Los Angeles, not on the customer's device. A phone in a
// different timezone (or with a wrong clock) otherwise computes a different earliest
// bookable date and a different weekday boundary than the salon does.
const SALON_TZ = "America/Los_Angeles";

function salonToday() {
    // en-CA gives YYYY-MM-DD directly.
    return new Intl.DateTimeFormat("en-CA", { timeZone: SALON_TZ }).format(new Date());
}

function salonDatePlus(days) {
    const [y, m, d] = salonToday().split("-").map(Number);
    const dt = new Date(Date.UTC(y, m - 1, d + days));
    return dt.toISOString().slice(0, 10);
}
```

Then:

```js
const datePIcker = flatpickr("#date-input", {
    inline: true,
    minDate: salonToday(),
    maxDate: salonDatePlus(30),
    allowInput: false,
    enableTime: false,
    dateFormat: "Y-m-d",
    disable: [
        date => date.getDay() === 1 //disable Mondays
    ],

    onChange(selectedDates, dateStr, instance) {
        clearTimeSelection();

        if (!serviceSelector.value) {
            showServiceRequiredError();
            return;
        }

        loadTimeSlots(dateStr);
    }
});
```
